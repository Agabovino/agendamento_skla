Preciso de ajuda para desenvolver a arquitetura, lógica de negócio e configurações de infraestrutura de um aplicativo de agendamentos semelhante ao Calendly. Considere que o back-end será em Node.js ou Ruby on Rails, o front-end em React, e tudo rodará em um servidor Ubuntu utilizando Docker. O domínio já está apontado via Cloudflare.

1. Infraestrutura e Conteinerização (Docker)

Forneça uma estrutura base de docker-compose.yml que orquestre de forma eficiente o banco de dados (ex: PostgreSQL), o back-end e o front-end.

Considerando que o tráfego externo virá pelo Cloudflare, qual a melhor abordagem para receber essas requições e fazer o roteamento para os containers da aplicação de forma segura no Ubuntu? (Sinta-se à vontade para sugerir a configuração de um proxy reverso em container ou soluções nativas do Cloudflare).

2. Integração com Google Agenda (Google Calendar API)

A aplicação precisa ter sincronização bilateral com o Google Calendar.

Ao ser realizado um agendamento, o sistema deve registrar o evento automaticamente na agenda do anfitrião.

Simultaneamente, deve disparar um convite para o e-mail do cliente, vinculando o compromisso à agenda dele. Forneça uma visão geral do fluxo de autenticação (OAuth2) e um exemplo do payload JSON necessário para a criação desse evento na API do Google.

3. Lógica de Negócio e Regras de Tempo
O sistema exigirá cálculos precisos de disponibilidade no back-end:

A duração base de cada agendamento é de exatamente 1 hora.

Deve existir um intervalo de segurança (buffer) obrigatório de 30 minutos entre compromissos de pessoas diferentes.

Flexibilidade de sessões contíguas: Um cliente pode reservar vários blocos de 1 hora em sequência. A regra matemática deve permitir blocos contíguos para o mesmo e-mail/usuário (ignorando o buffer de 30 minutos entre eles), mas deve garantir a aplicação do buffer antes e depois desse "bloco" caso o agendamento adjacente seja de outro cliente.

Por favor, forneça a modelagem de dados para o banco (tabelas de agendamento e disponibilidade) e os trechos de código do back-end essenciais para resolver a lógica dos horários contíguos com a validação do buffer condicional.
